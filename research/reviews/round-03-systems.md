下表是报告中的主方法近期分数 PPR，相对预先指定 Adamic–Adar 的最终留出结果；区间为该域、该年固定源图下的配对目标重采样区间。

这些结果支持“预先固定的评分器在多数观察年份有正的点估计差异，幅度与不确定性依领域/年份而异”，不支持“各域各年稳定显著优于基线”。它们更不验证导师、学历或晋升身份。各方法共享同一次采集和候选池，因而这次评分器比较的成本控制比跨查询策略的固定次数比较更清楚。

冻结 runner 在取得未来标签前完成采集及所有评分；forecast_features 只读取已返回事件，未发现把候选未经查询的全历史偷放入特征的路径。下一年标签中区分历史出现人物与冷启动人物，也与预先声明的任务一致。模型、参数和代码冻结机制是本轮主要改进。

## 仍需处理的工程问题

### P1：被拒绝输入仍可留下一个虚假候选

在核查的冻结版本中：

```python
s = Observation(1, 2000)
s.reveal(1, [(10, 1990, [1, 2])])
s.reveal(99, [(11, 1990, [1, 99])])
```

第二次 reveal 正确抛出“新事件违背已完成查询”的异常，但此前读取 `self.adj[author]` 已因 defaultdict 副作用插入作者 99；失败后 candidates 从空集合变成 `{99}`。这违反拒绝响应不修改状态的约定。冻结实验使用有效响应，此反例没有证明其已保存预测数值错误；不应为修这个边界而悄悄修改冻结组件后继续引用原指纹。

主线程已收到反例并拟实施冻结快照与 live 版本隔离。**验收条件**：新版本用无副作用查询并测试所有状态字段在拒绝前后完全一致；旧冻结组件原字节、协议和结果保留。快照重放应显式绑定所有传递导入、依赖、输入和独立输出目录。若复用原 holdout 检查点后直接跳过全部作者，只能叫重新汇总，不能称重算验证。本报告没有预先认定正在实施的快照方案已经通过。

### P1：冻结重放和检查点信任仍需更完整的验收

逐目标结果使用临时文件替换，能防止部分写入被当成完成；但现实现仅因文件存在就跳过，最后核对作者集合。应检查 checkpoint 中作者、年份、stage、方法集合和协议一致性，或建立最终逐文件摘要 manifest。损坏或错放的完整 JSON 不应通过目录名被默认为正确。恢复测试应覆盖合法 JSON 内容损坏、错误 stage，以及旧协议目录混入文件。

索引恢复与运行结果恢复属于不同层次，前者测试通过不自动证明后者成立。当前协议 alpha=0.85 与 PPR 默认值一致，结果没有因此错误；不过 runner 没有把协议 alpha 参数显式传给求解器，后续版本应避免“配置记了一个值，执行依赖默认值”的维护风险。

### P2：资源及线上迁移的主张仍需实测范围

现有本机已完成百万级事件索引与多千目标实验，足以否定此前未经测量的硬件终点假设。仍需清晰区分索引资源、查询缓存、评分与评价 oracle 成本；给随目标数/查询预算增加的峰值内存和时间曲线。完整作者查询在冻结数据内成立，OpenAlex 页数完成只证明对该次接口遍历完成，不能自动证明真实作者历史完整。不要在迁移到在线采集时直接复用离线证书的全部语义。

## 为什么当前仍是 5 分

文献计量面板、五种排名、经典图评分和 PPR 都已有成熟先例；将其集成、冻结并验证是必要研究基础。当前最有潜力的研究问题是有限观测下“候选发现、排序恢复与真实预测”的分解，但 CN 界、覆盖启发式和近期 PPR 尚没有被放入充分的既有主动查询/排名认证对照，相关工作和新贡献界限尚未完成。初始歧义补采方法没有显示稳定优势，也不能用后来成熟 PPR 的部分增益替代原有方法主张。

下一轮应提交一个围绕已验证结果的自洽研究论证：明确哪些结论是新发现，哪些只是已知工具；对最强既有方法做公平比较；说明负结果和跨领域不稳定性给出的可迁移认识。若要进一步提出新方法，应使用新的、诚实标明用途的验证设计，不能继续在本次最终留出上调参后称其为未见测试。排行榜稳定性与补采效益的联系、机会标签和高阶任务也尚未由本轮结果覆盖。

建议继续推进，保留这轮可复现成果，同时关闭原子性/重放边界并完成论文级贡献定位。内部评分达到中点以上必须由这些证据推动，不能靠更改评分口径或宣称硬件见顶。
