# 按需在线计算

首页只显示搜索主视觉及其下方内容。选中身份才获取论文，不预加载已有作者卡片。

## 数据生命周期

默认 Web 服务使用进程内 SQLite 内存数据库，不创建论文数据库文件，也不打开旧的 `scholartrace-web.sqlite`。源数据空间硬上限 512 MiB，写入分页前预留错误处理空间；达到容量时停止采集并说明原因，未完成的历史继续标为不完整。空闲 30 分钟清空整个临时工作区，服务重启也清空。侧栏可主动清空；运行中的采集和计算受到保护，不能同时清除。分页只在当前会话内恢复。旧研究文件不删除，用户主动导出仍可留存。

`SCHOLARTRACE_DB` 是显式的离线研究文件模式，不是线上默认配置。CLI 和冻结研究资料的行为不变。服务器进程不写密钥。这里的内存承诺指应用不主动持久化数据，不控制操作系统交换内存。

## 冷计算优化

1. 团队查询先从目标学者的论文确定直接合作范围，再按作者索引读取这些成员的历史；同机构、大团队和截止年条件都在选取候选时应用。其他用户查询过谁不再扩大这次观察集合，也不会导致扫描其论文。
2. 团队计算只解码身份、署名机构、日期、论文标识和撤稿状态等实际使用字段；不重复解析摘要、开放获取地址等大块元数据。年度计算额外读取参考文献及所需书目信息。原论文保留在当前临时工作区供检索和证据导出。
3. 数据源请求复用 HTTP 连接，避免每一页重新建立客户端和连接；同一采集任务合并。请求使用 `select` 仅下载现有功能需要的字段，仍保留摘要、参考文献和完整署名供检索与证据复核。团队历史最多 8 路并发获取，每位作者保留独立分页游标；被截断的论文署名也通过独立的有界请求池并发补取，共享同一连接上限和速率限制；作者资料使用最多 100 个 ID 的批量查询。全进程请求启动速率上限 8 次/秒，遇到 429/服务异常共享退避窗口。预计论文量较大的成员先启动，避免最后只剩一个大任务。手动小批次仍按原顺序采集，新目标进入等待队列。
4. 页面仅在数据或筛选变化时请求新的个人报告；未打开的图和论文列表延后绘制。进度轮询只查询当前作者。

新的网页年度网络范围为「目标及直接合作者已完成的历史」，并在界面与导出中写明。PageRank、社区划分和集合内引用依赖观察边界，不能同旧的「所有历史查询论文并集」数值无条件比较。团队输入摘要使用 `group-analysis-fields-1` 标记投影字段指纹；它不是原始 OpenAlex 完整响应的哈希。数学公式与冻结研究文件未改动。

## 完整团队分析的获取流程

点击「获取历史并计算」先显示当前数据的阶段性结果，再自动建立所选合作圈缺失成员的获取队列。重复点击或重新打开已有任务时复用当前队列。成员获取进度变化时，页面读取同一事务内的部分数据快照并更新图表；整批完成后自动计算最终结果。暂停与失败不会自行无限重启，用户可继续或重试。

「等待获取历史」指尚未获取或尚未翻完分页；「资料仍不足」指身份冲突、日期缺失等剩余证据问题。两者在卡片、年度图、表格和成员筛选中分开显示，网页导出的 `data_readiness` 记录对应人数。完整历史不能仅由老师自己的论文推断，所以首次完整团队分析需要逐个获取必要成员的历史；之前报告的 1.8 秒是数据齐备后的计算时间，不包括这段获取过程。

## 临时计算队列

团队与年度接口返回任务编号，页面跟踪真实的排队、运行、完成或失败状态。相同数据修订与参数的并发请求合并；计算过程中源数据变化则拒绝发布过期结果，页面最多自动重试三次。

计算结果只在内存暂存，空闲 10 分钟过期，同时最多 64 条任务记录、64 MiB 压缩结果；最多 2 个计算线程、16 个等待或运行任务。定时维护主动过期，不依赖下一次访问。任务编号使用随机值，重启后失效。之前新增的磁盘 `computations` 表在打开该数据库初始化时移除。

这些限制约束源数据与结果暂存，不是整个 Python 进程的最大内存；图计算临时对象会额外占用内存。超过限制会明确报错，不会截断历史再伪装为完整分析。

## 验证与适用范围

性能记录见 `research/results/online-calculation-latency.json`：同一份真实 Chao Huang 数据，三次未复用结果的团队冷计算由约 4.7 秒降至约 1.8 秒（包含接口响应；纯计算约 1.6 秒）。读取记录从整个库的 17,258 条缩至相关范围的 13,771 条。统计、成员、队列、子群、年度和老带新支持结果相同；证据中的个别作者显示名可能改为当前范围论文中的署名，不再从不相关查询补名字。该测试不包含向 OpenAlex 首次下载所需时间，不是公网并发压测。

验证包括未查询作者采集到计算、重复请求合并、任务容量与过期、源数据更新、失败重试、采集排队、无关作者隔离、默认运行不生成数据文件、临时库容量和运行中清理保护。

当前仍是本机单进程服务。公网多用户部署所需的身份隔离、每用户额度与进程外工作调度尚未实现；localhost 限制保留。当前改动解决按需计算与无持久化默认路径，不能据此宣称已具备公开服务规模能力。


## 来源获取接口与保护

实现依据 OpenAlex 官方的 [批量 OR 过滤](https://help.openalex.org/api/filtering/)、[字段选择与请求说明](https://help.openalex.org/api/llm-quick-reference/) 和 [分页规则](https://help.openalex.org/api/paging/)。每页继续使用受支持的 100 条。`authors_count` 不是可选字段，因此请求 `is_authors_truncated`；如有截断先获取单篇完整署名，只有完整列表才派生作者人数。单篇仍截断时明确失败，不把不完整历史标为完成。

只批量获取作者资料，不把多位作者的论文查询合为一个 OR 集合：每位作者的原始论文归属及身份冲突证据仍独立保留。暂停会作用于所有在途成员；当前页落入临时内存后停止，未开始的成员也保留待续状态。任一成员失败时停止派发新成员，等待已发请求收尾，不让后台线程失控。单成员的分页仍按游标顺序执行。进度同时报告完成成员、并发上限、累计耗时、请求量和传输量。


字段选择实网验证还修复了一个数据完整性问题：旧代码仅检查 `authors_count`，而返回记录可能只有 `is_authors_truncated`。Chao Huang 先前两位待判定成员的三条异常记录，均为仅返回前 100 位作者的截断记录。新实现补取完整署名后再判断身份，不能将这类截断解释为真实作者身份冲突。对应定向测试检查截断识别、补取后人数、补取仍截断时拒绝完成，以及并发补取的次序与暂停行为。


## 首次在线获取实测

`research/results/parallel-new-author-final.json` 记录空临时工作区中的 Rex Ying 查询：165 篇个人论文约 5.0 秒取得；82 位成员历史全部取得并完成画像约 46.9 秒，共 232 次团队获取请求，零次 429，待获取成员为零。上一轮尚未并发补取截断署名时，同范围为 77.8 秒；请求数与最终统计一致，缩短约 40%。对照见 `online-fetch-comparison.json`。这两次运行未控制外部 OpenAlex 缓存和网络状态，不能据此承诺所有作者固定速度；旧版完全串行的完整查询未重新进行同条件计时，不报告虚构的精确加速倍数。

首次显示个人内容和完整团队完成是两个不同时间点。完整团队时延仍随成员数、论文量、截断记录数量和来源响应速度变化；页面继续显示阶段性覆盖，而不是提前声称分析完成。
